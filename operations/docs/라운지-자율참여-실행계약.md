# 라운지 자율참여·실행 계약

## 목적과 범위

이 문서는 Slack `0_라운지`(`C0BNBDNC745`)에서 Staff의 참여와 Sinclair 실행 의도를 판정하는 기준이다. TSK-60 Issue A는 default-off admission과 Demian fast lane까지만 구현한다. Private Staff candidate 실행, candidate schema/parser, selector, Staff 공개 egress, Production enable은 후속 Issue 범위다.

## 불변 정책

- Staff는 기본적으로 Silent Observer다.
- Lounge의 공유 대화 Context는 유지한다.
- Sinclair가 특정 Staff를 호출하면 해당 Staff는 현재까지의 공유 Context를 전달받아 즉시 참여한다.
- 호출되지 않은 Staff는 기본적으로 발언하지 않는다.
- 다음 중 하나를 높은 확신으로 발견한 경우에만 Exceptional Interrupt 후보가 될 수 있다.
  - 명백한 사실 오류
  - 중대한 기술 또는 운영 리스크
  - 자신의 전문영역에서 결론을 바꾸는 결정적 충돌
- 관련 키워드가 있거나 추가 의견이 있다는 이유만으로는 개입하지 않는다.
- 자발적 공개 개입은 하나의 Sinclair source event에서 기본 1회로 제한하고, 이후 대화 주도권을 Sinclair에게 반환한다.
- Exceptional Interrupt 판단과 공개 발행은 Issue A에서 수행하지 않는다. 후속 selector/egress가 위 임계치와 1회 제한을 집행해야 한다.

## 라우팅 우선순위

1. 중복, malformed, unsupported Slack subtype, bot/self-echo는 no-op 처리한다.
2. Meeting control 또는 active Meeting은 기존 Meeting Engine 경로가 우선한다.
3. 기존 explicit single-team, explicit multi-team, `모두들` 호출은 기존 경로를 그대로 사용한다.
4. Sinclair의 명시적 실행 표현은 기존 승인형 실행/handoff 경로를 사용하며 spontaneous 후보를 만들지 않는다.
5. 실행 여부가 애매하면 Demian이 한 번만 확인 질문하고 Task를 만들지 않는다.
6. 위 경로에 해당하지 않는 이름 없는 Lounge discussion만 default-off spontaneous admission 대상이다.

새 admission은 `route_meeting_control(...)` 결과가 `None`인 경우에만 평가한다. 기존 Meeting Engine, explicit single-team/multi-team, TSK-58 Owner/PM workflow의 결정과 상태 전이는 변경하지 않는다.

## Thinking → Execution 계약

### Discussion

다음 표현은 토론으로 유지하며 Task, Owner, 새 Slack thread, artifact를 만들지 않는다.

- `~해야지`
- `대응해야지`
- `검토해보자`
- `어떻게 생각해?`
- 일반적인 Lounge 대화

### Execute

다음과 같이 의도가 명확한 표현은 existing execution/handoff path로 보낸다.

- `진행해`
- `착수해`
- `업무요청으로 넘겨`
- 구체적 대상과 함께 쓰인 `작성해줘`, `만들어줘`, `수정해줘`, `찾아줘`

### Clarify

`이거 해`, `처리 가능?`, `한번 해볼까`처럼 실행 여부나 대상이 불명확하면 한 번만 질문하고 fail closed한다. 확인 전에는 Task, Owner, thread, artifact를 생성하지 않는다.

## Admission과 Fast Lane

Admission은 feature flag `lounge_spontaneous.enabled=true`일 때만 열린다. flag가 없거나 `false`이면 candidate submission, candidate session, outbox, handoff를 새로 만들지 않고 기존 route 결과를 그대로 유지한다.

Admission은 다음 조건을 모두 만족해야 한다.

- exact Lounge channel
- Sinclair의 exact Slack user identity
- human channel message
- Meeting 및 explicit Staff 호출이 아닌 이름 없는 discussion
- 지원되는 Slack message subtype

Issue A의 `lounge_candidate_submitter`는 후속 durable private-child enqueue를 위한 injectable boundary다. 반환값이 awaitable이어도 source handler는 child completion을 기다리지 않는다. Demian의 material response는 candidate child와 독립적으로 처리하며 5초 acceptance budget을 갖는다. Child 실패는 source response를 실패시키거나 Staff 공개 발언으로 전환하지 않는다.

## Context 계약

- explicit Staff 호출과 future private candidate에는 같은 Slack thread의 bounded shared context를 전달한다.
- Context는 배경 자료이며 새로운 실행 권한이 아니다.
- 현재 검증된 Sinclair 메시지만 실행 지시 권한을 가진다.
- 다른 channel/thread, bot echo, 오래되거나 malformed인 이벤트를 Context 권한으로 승격하지 않는다.

## 검증과 Rollback

필수 회귀는 flag-off route 불변, Meeting precedence, explicit single/multi/`모두들`, bot/self-echo, unsupported subtype, trusted principal/channel, discussion no-work, execute existing path, clarify one-question/zero-work, slow-child nonblocking이다.

Rollback은 Production 설정을 켜지 않은 상태에서 Issue A commit을 revert하는 것으로 충분하다. DB migration, Gateway restart, live Slack canary는 Issue A에 포함하지 않는다.
