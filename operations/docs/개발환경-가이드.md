# Hermes 개발 환경 가이드 — Hermes Desktop + VS Code 병행

## 1. 기본 원칙

Hermes 개발은 **Hermes Desktop과 VS Code를 병행**한다.

- **Hermes Desktop:** 개발 지휘실
- **VS Code:** 실제 개발 작업장

두 도구의 역할을 나누되, 모든 변경은 `/opt/data/ARCHITECT.md`의 개발 절차를 따른다.

## 2. 도구별 역할

### Hermes Desktop

다음 업무를 담당한다.

- 요구사항 정리
- 구현 범위와 기대 결과 정의
- 설계 및 영향 범위 검토
- AI 개발 작업 지시와 조율
- 코드 리뷰와 회귀 테스트 지시
- 테스트 결과 및 운영 상태 확인
- 배포 승인과 최종 결과 검증

Hermes Desktop에서 즉흥적으로 운영 코드를 직접 수정하지 않는다. 먼저 분석·계획·승인을 거친다.

### VS Code

다음 실무를 담당한다.

- 코드와 문서 편집
- Git diff 및 변경 파일 비교
- 검색과 참조 추적
- Python 디버깅과 중단점 확인
- 통합 터미널에서 테스트·lint·Git 작업
- overlay와 운영 파일의 차이 확인

## 3. 권장 VS Code 연결 방법

1. VS Code에서 **Dev Containers: Attach to Running Container**를 실행한다.
2. 실행 중인 Hermes 컨테이너에 접속한다.
3. `/opt/data`를 작업 폴더로 연다.
4. Python 인터프리터를 `/opt/hermes/.venv/bin/python`으로 지정한다.
5. Git diff와 테스트 결과를 확인하면서 `/opt/data`의 소스·문서·runtime overlay를 편집한다.

## 4. 파일 수정 및 배포 원칙

- `/opt/hermes` 운영 파일을 VS Code에서 바로 편집하지 않는다.
- 개발 원본과 runtime overlay는 `/opt/data` 아래에서 수정한다.
- 승인된 범위만 구현한다.
- 문법 검사와 회귀 테스트를 통과한 뒤 운영에 배포한다.
- root 소유의 `/opt/hermes` 반영은 승인된 배포 절차에 따라 root 권한으로 수행한다.
- 배포 후 overlay와 운영 파일의 SHA-256, 실제 import 경로, 새 프로세스 PID와 로그를 확인한다.
- Gateway 재시작은 자기 자신을 호스팅하는 Gateway 내부가 아니라 외부 셸 또는 승인된 관리 스크립트에서 수행한다.

## 5. 표준 개발 흐름

```text
Hermes Desktop
요구사항 정리 → 설계 → Sinclair 승인
                    ↓
VS Code
코드·문서 편집 → diff 확인 → 디버깅 → 테스트
                    ↓
Hermes Desktop
리뷰 → 회귀 테스트 확인 → 배포 승인 → 운영 검증 → 결과 보고
```

세부 절차는 다음 순서를 고정한다.

1. 분석
2. 수정 계획 작성
3. Sinclair 승인
4. 코드·설정·문서 수정
5. 테스트
6. Commit
7. 배포 및 결과 보고

## 6. 변경 이력

모든 개발·배포 변경은 `/opt/data/workspace/changes/` 아래에 변경 이력 문서를 남긴다.

변경 이력에는 최소한 다음을 포함한다.

- 작업 목적
- 변경 파일
- 변경 내용
- 영향 범위
- 테스트 결과
- 남은 이슈
- 복구 방법
- 다음 작업

## 7. 금지 사항

- 설계와 승인 없이 코드부터 수정
- `/opt/hermes` 운영 파일 직접 편집
- 검증 없이 Gateway 재시작 또는 배포
- 관련 없는 리팩터링을 함께 수행
- 운영 자격증명과 토큰을 문서·로그·대화에 출력
- Hermes Desktop과 VS Code에서 같은 파일을 동시에 수정해 변경 충돌 유발

## 8. 완료 기준

개발 작업은 다음 조건을 모두 충족해야 완료로 본다.

- 승인된 요구사항과 설계를 충족함
- VS Code에서 diff와 변경 범위를 확인함
- 문법 검사 및 관련 테스트가 통과함
- 기존 기능의 회귀 여부를 확인함
- 운영 반영 시 실제 프로세스와 로그로 검증함
- 변경 이력과 복구 방법을 기록함
- Hermes Desktop에서 Sinclair에게 결과를 보고함
